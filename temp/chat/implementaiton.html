📌 Project Overview & Technical Stack

This Task Manager application is built for the Hammoq Technical Assessment to demonstrate enterprise-grade MERN stack engineering, clean architecture adhering to SOLID principles, strict Dark & Light theme support across every component, and live integration with MongoDB Atlas.

Frontend Stack

  • React.js 18 with Vite
  • JavaScript (ES6+) – No TypeScript
  • Modular CSS with CSS Design Tokens
  • ThemeContext for dynamic Dark/Light switching
  • Centralized API Service using native fetch

Backend Stack

  • Node.js & Express.js
  • MongoDB Atlas & Mongoose ODM
  • Target Database: Hammoq
  • Target Collection: tasks
  • Centralized Error Handling & Validation

🏛️ Architectural Decisions & SOLID Principles

User Rule 1: Comprehensive Dark & Light Theme

Implemented through semantic CSS variables defined at :root and [data-theme='dark']. All typography, card backgrounds, borders, inputs, modals, table rows, and badges dynamically transition without layout thrashing. The theme preference is automatically detected from the user's OS and persisted in localStorage.

User Rule 2: Strict SOLID Adherence

Single Responsibility (SRP): Separate modules for DB connection, models, controllers, routes, error handling, API services, and UI components.
Dependency Inversion (DIP): UI components depend on abstract API service contracts (api.js) rather than direct HTTP calls.
Open/Closed (OCP): Easy extensibility for new endpoints or theme tokens without modifying core logic.

💻 Visual Dashboard & Feature Showcase

The responsive Dashboard layout includes live metric summary cards, search and multi-filtering, inline status cycling, creation/edit modals, and deletion confirmation safeguards.

🔌 Backend REST API Specification

Method Endpoint Parameters / Body Purpose & Status Code
GET /api/hello None API connectivity verification (200 OK)
GET /api/tasks search, status, priority, sortBy, sortOrder Retrieve tasks list + real-time dashboard counts (200 OK)
GET /api/tasks/:id id (MongoDB ObjectId) Retrieve single task by ID (200 OK / 404 Not Found)
POST /api/tasks { title, description, status, priority, dueDate } Create task with validation (201 Created / 400 Bad Request)
PUT /api/tasks/:id Updated fields Update task by ID (200 OK / 400 / 404)
DELETE /api/tasks/:id id (MongoDB ObjectId) Remove task by ID (200 OK / 404 Not Found)
